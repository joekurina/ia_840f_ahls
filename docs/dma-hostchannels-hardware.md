# DMA-backed kernel host channels: hardware source candidate

> **Historical experiment — outside the standard/USM BSP baseline.** This document preserves an earlier custom host-pipe investigation. Its transport choices, widths, CSR addresses and integration instructions are not requirements or approvals for the vendor-based modernization. Host pipes may enter the BSP only through an established reference-platform implementation; see [current preparation scope](preparation-plan.md). Do not execute the instructions below under the source-only authorization. Statements about candidate source locations describe the earlier experiment, not necessarily the active baseline after preservation/disconnection.


## Transport contract (before implementation)

This candidate implements `interfaces/dma_hostchannel/transport-contract.md`: byte MMIO base 0x30000, two 0x100-byte slots, identity 0x4941383448430001, slot 0 `host_to_kernel` (MMD H2D=1), slot 1 `kernel_to_host` (D2H=0), 512-bit/64-byte elements. Ring addresses are DMA IOVAs, not VTP virtual addresses. Ring capacity is a power of two from 64 through 2^31 bytes. Positions are unsigned monotonic 64-bit byte counters, never masked except when calculating an address. Counter rollover requires quiesce/reinitialize; it is rejected rather than allowed to alias live credits.

CONTROL bit0 RUN and bit1 QUIESCE are level state; bit2 RESET_POSITIONS is a command accepted only while QUIESCED. RESET_POSITIONS disables RUN, clears both positions, internal prefetch/issue positions, retained FIFO contents and errors. Configuration may change only while QUIESCED and after RESET_POSITIONS (all positions zero). Full-width aligned 64-bit CSR accesses only. Unsupported writes latch an error. ERROR is sticky and cleared by RESET_POSITIONS, not W1C.

H2D: the host publishes HOST_POSITION after release-ordering ring data and completing any required DMA cache synchronization. Hardware reserves bounded FIFO space **before** each host read. DEVICE_POSITION advances only when a successful DMA response has been copied into the FIFO. Host reclamation therefore does not depend on kernel consumption. A full FIFO stops further reads. Read responses are in order through the PIM Avalon service; failed responses stop fresh requests and never publish data. Each request is one aligned full cache line, so no request crosses a ring boundary or a 4 KiB boundary.

D2H: kernel words enter a bounded FIFO. Ring credits are reserved at DMA issue; host release updates cannot move beyond DEVICE_POSITION. Full rings backpressure DMA and eventually the kernel. A batch of payload writes is followed by a PIM write fence. Normal write acceptance/response is **not** publication. Wait for the fence's response before advancing DEVICE_POSITION. The pinned PCIe PIM implements a fence as a PCIe memory read of the most recent write address and returns its response after that read completes. Keep payload and fence on the same ordered PIM write stream, with relaxed ordering disabled by the PIM. MMIO readers must use the runtime/driver's DMA acquire/cache-synchronization operation after observing DEVICE_POSITION. There is no completion-record DMA or IRQ in this baseline: progress is polled through MMIO.

QUIESCE stops fresh H2D requests and stops D2H kernel admission. Already accepted requests retire. D2H retained FIFO data may be discarded by RESET_POSITIONS; quiesce is not a promise to transfer data that was never issued. QUIESCED means no pending or presented DMA request, no pending response, and no unfenced issued write can touch the ring. H2D prefetched words may remain on FPGA; quiescence does not require a running kernel. Ring mappings must remain pinned until QUIESCED. A timeout is not cancellation: retain mappings until a platform reset with proven PCIe drain or a later quiescence acknowledgement.

## Inspected source and integration boundary

- ASP `common/build/rtl/dma/dma_top.sv` instantiates independent host-to-DDR and DDR-to-host `dma_data_transfer` engines. Those are not kernel pipes and are preserved.
- `afu.sv` uses `host_mem_if_vtp.sv` to translate DMA and USM virtual addresses and mux their physical traffic; `ofs_plat_afu.sv` maps physical PIM Avalon host-memory interfaces to PCIe.
- `asp_host_mem_if_mux.sv` injects DDR DMA IRQ/fence sideband requests. Do not insert an untagged request-level arbiter in this path or steal its responses.
- The reusable PIM `ofs_plat_avalon_mem_rdwr_if_mux` preserves complete write bursts, round-robin arbitrates sources and routes read/write responses using trackers. A new **physical** host-memory mux outside the existing VTP subtree can preserve the existing subtree as one source and use two independent hostchannel sources. No new VTP service or hand-coded PCIe packets are needed.
- PIM `ofs_plat_host_chan_avalon_mem_pkg.sv` defines `HC_AVALON_UFLAG_FENCE`; `native_axis_pcie_tlp/prims/ofs_plat_host_chan_GROUP_gen_wr_tlps.sv` tracks the last write address, emits a read for fences and holds fence metadata until read completion. Do not use NO_REPLY for payloads/fences in the new engines.

This is source-only, not generated-design compatibility, synthesis, timing, simulation, bandwidth or hardware proof. Compiler-generated hostpipe ports and their clock/reset adaptation remain an explicit integration gate; a CSR-backed hostpipe sample does not satisfy it. No builds, configuration, IP generation, simulation, tests or vendor tools are authorized here.

## Implemented source

Under `oneapi-asp/common/hardware/common/build/rtl/hostchannel/`:

- `asp_hostchannel_pkg.sv`: exact shared ABI v1 identity, offsets and error masks.
- `asp_hostchannel_fifo.sv`: real bounded same-clock FIFO storage, pointer/count state and ready/valid backpressure; default 64 words in each direction. Storage inference/timing is not qualified.
- `asp_hostchannel_engine.sv`: parameterized ingress/egress controller, per-slot CSRs, capacity/position validation, pipelined aligned PCIe-memory requests, bounded outstanding tracking, D2H batch/fence FSM and reset/quiescence handling.
- `asp_hostchannel_share.sv`: reuses the PIM three-source Avalon mux; preserves the legacy DMA/USM/VTP subtree and its full bursts/responses/IRQ flags. Adds D2H write exclusion described below.
- `asp_hostchannel_integration.sv`: complete two-engine physical-host-memory sharing and MMIO interception wrapper, with explicit synchronous 512-bit kernel streams. It is not an empty shell or a fabricated compiler port adapter.
- `asp_hostchannel_sources.tcl`: source order/list. The existing `asp_design_files.tcl` now includes this list, **definitions only**. It does not instantiate or advertise hostchannels.

Default H2D admission can keep up to 64 cache-line reservations between outstanding reads and buffered responses; it never relies on read-response backpressure, which Avalon does not provide. D2H issues up to 32 single-line payload requests per batch, then drains ordinary responses and waits for a real fence response. Consecutive payload requests are supported when credits/data are available. These are source bounds, not measured throughput. One-cache-line TLPs, fence turnaround, CSR polling and admission exclusion may limit bandwidth; no line-rate claim is made.

### Why write exclusion is present

A plain shared mux is insufficient for safe fence-address lifetime. The PIM fence reads its **last write address**, not an address selected by the fence's caller. If an unrelated DDR/USM write interleaves before the fence, its allocation might be released independently. `asp_hostchannel_share` therefore stops admitting new legacy write bursts, finishes an already-started legacy burst, waits for all accepted legacy write responses, and gives the D2H batch exclusive write admission through fence completion. Reads remain shared throughout. It then releases admission for legacy traffic between batches. This also means legacy IRQ write requests may wait behind a D2H batch/fence; no latency guarantee is claimed.

At the exposed physical AFU source boundary, each legacy write burst must request a response (`NO_REPLY=0`); PIM may set NO_REPLY internally when splitting later. A NO_REPLY burst, zero-length burst or unsolicited response latches `share_fault`, feeds both engines' protocol error/poison state, and requires platform-level reset/drain recovery. Ignoring a missing response would falsely grant exclusive ownership while a legacy write was still buffered. The existing ASP's explicit DMA/IRQ request formation clears NO_REPLY. The generated VTP/PIM closure must also be checked before enabling the wrapper.

### Error and lifecycle details

ERROR bits: bit0 malformed/unsupported CSR access; bit1 configuration mutation or invalid start configuration; bit2 invalid position/position exhaustion; bit3 reported nonzero memory response; bit4 response accounting/protocol/share fault. Errors inhibit new requests and kernel admission but never cancel a presented request under waitrequest. Already-accepted responses are retired. Unexpected responses or a reported failed fence poison quiescence: software must not free mappings on a timeout. A normal response error is sticky; a successful final fence may still permit safe quiescence, without publishing errored data.

`CONTROL=2` requests quiesce, poll STATUS bit1, then `CONTROL=4` resets positions/FIFO/error state and leaves RUN=0, QUIESCE=1. Program RING_IOVA and RING_BYTES, then publish H2D data/position as appropriate and use `CONTROL=1` to run. Configuration writes require both positions zero and a clean epoch established by reset; merely writing RUN=0 cannot authorize live-ring reconfiguration. `CONTROL=5` is rejected (reset must not simultaneously run). Resetting positions retains the address/capacity configuration. The reset command discards unissued buffered stream words explicitly. Global `reset_n` is a platform reset, not a software DMA-cancellation mechanism: platform teardown must guarantee no old response can enter a new epoch.

STATUS RUNNING describes enabled scheduling, not host activity. QUIESCED permits retained FPGA FIFO words and means no pending/presented DMA or unfenced issued write remains. Resume without RESET_POSITIONS retains those words. For reliable application shutdown, first finish the application's stream protocol and observe its output; quiescence alone does not flush every kernel-accepted word into host memory.

The pinned PCIe Avalon mapper sets `rd_response` and `wr_response` to zero (`ofs_plat_host_chan_GROUP_map_as_avalon_mem_if.sv`, around lines 373 and 599). Thus the engine's nonzero-response handling is real logic but cannot invent PCIe error information absent from that adapter. Missing completions hold outstanding state and prevent quiescence. A platform PCIe/AER fatal-error path and DMA cache-coherency contract still require qualification; do not interpret zero Avalon response as comprehensive PCIe error reporting.

## Necessary top-level integration changes (not yet applied)

No compiler-facing hostpipe ports have been invented. `ofs_plat_afu.sv`, `afu.sv`, `asp_logic.sv`, `board.ip`, generated `board`/`kernel_system` RTL and existing DMA RTL remain unchanged. Until the following binding is source-grounded and applied, the new engines are **not reachable in a board image**, and MMD must keep the capability disabled.

1. In `ofs_plat_afu.sv`, declare an additional `ofs_plat_avalon_mem_rdwr_if` array for the legacy AFU using the exact parameters of `host_mem_to_afu`; drive each added interface's clock/reset/instance number from the corresponding existing physical interface. Declare an added 64-bit legacy MMIO interface with the same parameters/clock/reset as `mmio64_to_afu`.
2. Instantiate `asp_hostchannel_integration`: connect `host_mem` to `host_mem_to_afu[HOSTMEM_CHAN_DEFAULT_WITH_MMIO]`, `legacy_host_mem` to the corresponding added interface, `mmio` to `mmio64_to_afu`, and `legacy_mmio` to the added MMIO interface. For any other host-memory channel use `ofs_plat_avalon_mem_rdwr_if_connect` unchanged between physical and legacy arrays. Change only `afu_inst.host_mem_if` and `.mmio64_if` to the new legacy array/interface. Do **not** insert below the VTP translator, replace the DDR DMA engines, bypass response routing, or connect IOVAs to a VTP-VA port.
3. Propagate the two named streams through explicit ports in `afu` and `asp_logic` to the actual compiler-generated non-CSR hostpipe endpoints. Determine their real signal names, element packing, direction and readiness semantics from authoritative compiler artifacts. The wrapper currently requires readyLatency=0 and `host_mem.clk`/`host_mem.reset_n`; a generated endpoint in `uClk_usrDiv2` with a different clock requires a real dual-clock FIFO/reset coordination adapter before attachment. Never tie ready permanently high or bridge clocks combinationally to make a port list appear complete.
4. Keep the CSR interception **before** legacy address truncation. `asp_logic.sv` forms its Qsys MMIO address from the PIM word address; the wrapper expands that word address by three bits and compares the full 0x30000..0x30fff byte range. Legacy accesses are forwarded untouched; reads are serialized to maintain response ownership. The current legacy path uses registered read responses. All local accesses must be full 64-bit single-beat accesses; invalid local reads return SLVERR, and reserved-slot writes report CSR error in slot 0.
5. Gate capability advertisement and board channel metadata on that exact binding and the subsequent separately-authorized generated-design/CDC/PCIe qualification. The existing DDR-DMA and USM feature selections remain intact. This source work opens none of those gates.

## Source-review boundary

The transport and bounded-state logic were inspected against the pinned PIM interface declarations, mux routing, fence TLP generation/completion and existing ASP source. No HDL parser, elaborator, simulator, test runner, build/configure step, IP generator, vendor tool or remote operation was run. Tool-confirmed file writes establish source creation only. Subsequent authorized verification must cover simultaneous enqueue/dequeue and request/response, stalled quiesce, failed/missing completions, ring wrap, reset epochs, legacy multibeat bursts/IRQs/VTP traffic, both CSR windows, and end-to-end generated hostpipe/CDC binding before functionality or performance can be claimed.
