# Native-clock observer slice — spec review

**PASS — no blocking defect found in the bounded passive observer slice.**

Reviewed `../DESIGN01.md` §§2–3, applicable local fault semantics from §5, `PLAN.md`, the actual observer and testbench RTL, `RESULT.md`, `test-final.json`, `negative-control.json`, and the actual negative-control mutant. This verdict covers native-clock accounting and synchronous epoch commands, not mailbox/CSR/physical integration or hardware qualification.

## Requirement findings

| Requirement | Finding and evidence |
|---|---|
| Passive, handshake-only accounting | **PASS.** All AXI signals are inputs. `af/wf/bf` gate updates; A/B count transactions, Q counts declared beats, W/L count accepted data/last beats, and T counts WSTRB population (`ia840f_ahls_write_observer.sv:9–28,39–48,60–68`). No channel is driven or stalled. |
| Widened simultaneous next state | **PASS.** Each total is extended before addition; all same-edge increments feed the same next-state fault/checkpoint calculation (`:31–33,63–91`). The maximum AW increment is 256 and fits the extra bit even at the minimum permitted width8. WSTRB population fits its seven-bit accumulator. The simultaneous-channel test checks the aggregate arithmetic (`tb_write_observer.sv:78–81`); it is not proof that this zero-history stimulus represents a legal AXI slave response latency. |
| W-before-AW legality | **PASS.** Independent cumulative Q/W and A/L totals are retained. Only B>A or B>L is rejected; there is no busy-time W<=Q or L<=A constraint (`RTL:78`). W-before-AW is explicitly accepted and subsequently retired (`TB:74–76`). |
| Enabled bytes versus outstanding responses | **PASS.** `empty` is exactly A=B, Q=W, L=A. C advances to next T only at a fault-free complete checkpoint; it is not treated as a precise per-response byte count (`RTL:49,85–87,111–112`). Partial tail masks, incomplete output, delayed final W/B, and multiple fragments are checked (`TB:59–72`). An early error B permanently prevents certification (`TB:83–85`). Byte equality alone cannot retire outstanding responses. |
| Exact epoch predicate | **PASS.** Both public target and internal RELEASE qualification require armed, no errors, empty, non-underflowing deltas, and **both** T-base=E and C-base=E (`RTL:50–53,88–91`). Smaller totals remain pending; excess enabled bytes latch a fault (`:81–82`). Empty upstream gaps do not pass. Baseline is frozen at a clean ARM; a subsequent epoch uses cumulative history (`TB:67–68`). |
| Error precedence | **PASS.** Every accepted non-OKAY B, wrong physical ID, B-credit violation, overflow, excess, synchronized DMA contamination/link fault, and invalid command poisons success. Command faults also undo tentative C advancement. Existing error bits and first-error history persist; simultaneous first faults select the lowest-numbered code (`RTL:75–84,101–122`). Tests cover all non-OKAY response encodings, held B before acceptance, target/error coincidence, and retention of the first error (`TB:83–95,115–124`). |
| Saturation | **PASS.** A/B/Q/W/L/T clamp rather than wrap, and overflow permanently blocks target and C advancement (`RTL:69–80,111–112`). C only copies clean T. Narrow tests reach beat, byte, and transaction saturation. An ARM near exhaustion can later fail closed; the module does not promise that every accepted epoch has remaining counter capacity. |
| Token and command behavior | **PASS.** ARM requires disarmed, clean empty state, no presented AW/W/B, valid positive aligned expected volume within the bound profile, and a nonzero token different from the previous epoch (`RTL:93–101`). Rejection retains epoch fields and latches command error. SNAPSHOT is a local no-op; RELEASE requires error-free exact retirement and no presented write-channel activity (`:103–108`). Reset clears armed/target lineage rather than preserving completion (`:126–134`). The no-BVALID guard is conservative, not an unsafe relaxation of the design. |

## Reuse boundaries and limits — not missing-integration defects

- **`cmd_valid` is an edge-by-edge command strobe, not a held mailbox request.** Every asserted edge executes the command; holding ARM or RELEASE through a second edge can cause a sticky invalid-command fault. `cmd_ack` acknowledges processing, including rejection, and is not a success indication (`RTL:93–109,134`). A future adapter must pulse requests and examine the resulting state/errors.
- **SNAPSHOT does not freeze these outputs.** Counters and target remain live native-clock state. Neither `empty` alone nor an old target sample is a reusable completion certificate. The deferred mailbox must supply coherent, fresh, matching-token snapshots and the required live-fault handling.
- The code2 diagnostic payload chooses offending AWID when present, otherwise BID (`RTL:120`). A future CSR mapping must not describe that payload unconditionally as BID; the proposed CSR ABI is not implemented by this slice.
- DMA/link inputs are assumed already synchronized sticky indications. This module does not establish the upstream ARM-enqueue-to-RELEASE fault window or reset-safe CDC lineage. Those are explicit future obligations, not grounds to fail this review.
- Directed coverage is not exhaustive: no actual splitters/CDC/vendor path, full positional AXI checker, default-width overflow stress, or all multi-fault/command boundary combinations were exercised. Fragment traffic is injected at the stated observer boundary.
- **TARGET_RETIRED only.** Host ownership, known pre-start lineage, exact finite output-volume and legal/non-duplicating transport premises remain necessary. The slice does not prove addresses/numerical results, HLS completion, post-B DMA visibility, absence of future zero-strobe commands, global drain, or reset safety. Deferred integration is neither approved nor demanded by this PASS.
