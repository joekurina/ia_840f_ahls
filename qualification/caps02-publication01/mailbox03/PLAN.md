# Two-clock observer mailbox — integration slice

Add a standalone bundled-data request/ack mailbox alongside unchanged candidate02. Core requests pulse ARM/SNAPSHOT/RELEASE with frozen expected/token fields; native commands are one-cycle strobes into the actual observer. Native response captures the whole live observer payload only after its command acknowledgement. Core installs a frozen coherent snapshot and increments a non-wrapping sequence after synchronized acknowledgement. No direct memory-interface outputs, vendor logic, live device or remote execution.

Reset: either reset asynchronously invalidates mailbox request/response state; deassertion is independently synchronized. Observer receives the joined native link reset. The core separately retains an ARM-enqueue-to-successful-RELEASE-ack epoch window and faults if native reset interrupts it. A core reset clears local lineage and also invalidates native observer state, never replays a stale command. Software must treat any reset as a lost/unknown invocation, not cancellation. This changes only new observer logic reset, not memory/FIM reset topology.

DMA attempts are monitored in core clock from ARM enqueue (including that edge) through RELEASE acknowledgement. Sticky contamination crosses to the native observer; core fault remains directly visible. Native error is synchronized back, with captured errors also included in the coherent payload. Invalid requests and sequence overflow poison local status. A halted native clock leaves command busy, not a blocked MMIO response; mailbox outputs are core registers. Clock constraints and real CSR local-response integration remain unaccepted until integrated native tool checks.

Acceptance: real local RTL simulation connects this mailbox to the actual candidate02 observer, with distinct clock periods. Check clean ARM/exact retirement, immutable snapshots during later native traffic, delayed finalB, command-pulse count, busy rejection, stopped native clock and subsequent response, idle/active native reset, core reset/stale-request suppression, contamination from enqueue, invalid token response and sequence monotonicity. Do not call this hardware, native AXI-controller or vendor DDR simulation.

FIRST_ERROR code2 ID metadata can denote offending AWID or BID; future CSR documentation must not promise it is always BID. Proposed existing CAPS02 offsets remain inaccessible on deployed CAPS01. TARGET_RETIRED does not become PUBLISHED through this mailbox.
