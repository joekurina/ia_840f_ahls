## Remaining before live DMA

Independent code/test review `deleg_db9aa705` is pending. This report is a factual preparation result, not that review's acceptance or hardware authorization.

A DMA runtime supervisor must preserve the owning application **and its container PID-namespace init** after HOLD or timeout. Do not mechanically reuse the identity-only inner runner's exception-to-exit path: with `--containall`, exiting PID1 can terminate the remaining application even without an explicit kill in Python. The new inner supervisor must persist the failure record then remain alive without more device access; its outer observer may return an UNKNOWN/retained-owner result without destroying the container. Test this behavior with an inert child before any VFIO exposure. Do not treat a software deadline as cancellation or reclaim an uncertain owner.

Bind the new binaries plus the previously accepted runtime closure and preserve the empty read-only CWD. No live DMA, DDR data or AHLS numerical test has been performed. Local retirement plus host-memory verification is this candidate's bounded completion contract, not a general PCIe drain/reset guarantee or sustained/full-DDR qualification.
