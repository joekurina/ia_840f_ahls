## S1 — timeout can leave the owned native process group running

**Location:** `generation-candidate-02/run_generation.py:126–133`.

On timeout the runner sends SIGTERM to the stage process group, but decides whether to send SIGKILL solely by waiting for the immediate child. If the launcher exits on SIGTERM while a descendant in the same group ignores SIGTERM, `child.wait(timeout=10)` succeeds and the SIGKILL branch is skipped. The runner records rc124/failure and returns while that descendant is still running. This fails the bounded stage/process-group termination requirement and can leave native writes continuing after the failure report.

**Independent inert reproduction:** In a fresh local package copy, replace only fixture preflight/dependency checks and stage argv in memory. Launch `/usr/bin/python3 -B -c ...` with the actual runner's `start_new_session=True`; the Python stage forks, the descendant ignores SIGTERM, and both sleep. Set the fixture stage timeout to one second. Actual runner returned `NativeStageFailure` rc124 and persisted a failed result with every readiness flag false. Immediately afterward `/proc/323913/stat` showed the descendant still in state `S`, process group/session `323912`, after the launcher had exited. The reviewer then killed only this owned inert descendant. No vendor executable was involved.

**Minimal correction:** Track the owned stage process group independently of immediate-child exit. After the TERM grace interval, ensure surviving members of that same owned group receive KILL, handling an already-absent group without replacing the original timeout status. Preserve rc124, exclusive claims/logs, and failed evidence. Add an inert regression for a TERM-exiting launcher with a TERM-resistant descendant, asserting no live descendant remains when the runner returns and reruns cannot mutate retained evidence. No generic monitor redesign, new project interrogation, or permission expansion is requested.
