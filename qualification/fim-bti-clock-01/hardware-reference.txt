2 Board Overview

The IA-840f is a full-height, ¾-length, double-width, PCIe Gen4 x16 card with an Intel Agilex FPGA. The
FPGA is connected to three QSFP-DD ports and up to 128GB DDR4. The IA-840f supports both active and
passive cooling options.

3.1 Handling, Unpacking, and Shipping Tips

           Warning! The IA-840f contains electro-static discharge (ESD) sensitive devices. Be sure to follow
           the standard handling procedures for ESD sensitive devices, taking proper precautions to ground
           yourself and the work area before removing the board from its static shielding bag. If you fail to fol-
           low proper handling procedures, you could damage the board.



3.1.1 ESD Handling Tips
Effective ESD control and proper ESD handling will maintain the reliability of your BittWare
products. Please follow the guidelines listed below to avoid ESD damage to the IA-840f.
   l   Transport the board only in ESD shielding bags or shielding containers.
   l   Do not remove the board from its static shielding bag when outside an EPA (ESD Protected Area).
   l   Wear a grounding wrist strap when handling the board. BittWare also recommends using foot/heel
       straps in combination with static dissipative flooring.

3.6 FPGA Configuration
The IA-840f automatically loads an FPGA design from Flash at power on. There are several ways to pro-

JTAG Chain using on-board USB-Blaster II – The IA-840f features a Max 10 FPGA which hosts a
USB-Blaster II to access the FPGA JTAG chain. Connecting to the board via USB allows access to the
JTAG chain with Quartus Programmer. Using this method, you can reconfigure the FPGA directly. The




© 2025 BittWare, a Molex company                                                                          29
JTAG chain also provides debug access to the board and enables the use of various JTAG-based
debug utilities such as Intel’s Signal Tap Logic Analyzer and Intel’s System Console.
User Flash Interface – There are currently two ways in which the QSPI Flash can be programmed: Pro-
gramming via JTAG (using the Quartus programming tools and a .jic file) or programming via the SDM
(using the Intel SDM Mailbox Client IP block within the FPGA design). The latter method requires a .rpd

design at the next power cycle or after you launch a soft reconfigure request. For more detail on pro-
gramming the flash, refer to the IA-840f FPGA Developer Guide.
Soft Reconfigure – Issue a command to the SDM Mailbox Client to trigger a reconfiguration of the
FPGA from one of the two bitstreams stored in flash.
For details on FPGA configuration, refer to the IA-840f FPGA Developer Guide.

5.2.1 PCIe Enumeration
The PCIe specification requires that a PCIe endpoint be ready for PCIe enumeration within 100ms of the
host system powering on. Agilex by default uses an autonomous HIP mode which brings up PCIe before

out of reset within 100ms of power on. However, this requirement is more often widened by host servers
and workstations effectively allowing the FPGA for more to complete its configuration.

5.2.3 PCIe Reset Requirements
Since the IA-840f is a PCIe card, it is a slave to a host processor that is the root complex of the PCIe bus.
Therefore, the reset for this board comes through the PCIe bus from the host.
The mechanism that supports a reliable initialization of the firmware and software running on the IA-840f
is as follows:
  1. The board powers up and supplies are sequenced by the BMC, after which the board comes out
     of reset.
  2. When the power supplies are stable, the BMC green LED comes on (D15), the configuration logic
     is released, and the FPGA configuration starts.
  3. The BMC then programs the clock chip.
  4. After FPGA configuration, PCIe training and reset should occur.
  5. The release of the PCIe reset by the host also deactivates the global reset to the internal FPGA
     design.
  6. After PCIe enumeration, a soft reset comes from the PCIe core to the rest of the internal FPGA
     logic to start the firmware.

reference clock frequencies might be required. The QSYS IP Library contains several pre-set files and

protocols.

8.2.1 PCIe Clock
The PCIe clock is 100MHz and is provided by the host motherboard by default, or an on board source for
standalone applications . This clock is routed to an IDT 9DML2855 and duplicated six times to provide a
PCIe clock to all PCIe resources on board:
   l   FPGA SerDes banks for the PCIe host interface
   l   Two LMK00334RTVR clock buffers
The Intel PCIe IP must use these reference clocks. Each output uses the 1.8V HCSL I/O standard.
See the PCIe standard specification for more information.
   l   FPGA pin name (QSF) for PCIe host I/F (on-board PCIe clock buffer): pcie_refclk[0]
   l   FPGA pin name (QSF) for PCIe host I/F (on-board PCIe clock buffer): pcie_refclk[1]

8.2.2 User Clock
An on-board clocking circuit feeds a 100MHz LVDS DC coupled clock signal to the FPGA. This clock is
for general clocking of the fabric.
This clock is sourced from an output of a Silicon Laboratories Si5397A synthesizer fed by a 48MHz crys-
tal oscillator. The Si5397A is I2C controllable from the BMC (it is not recommended that this clock is
changed from its default frequency; however, if this is required contact BittWare for details).
FPGA pin name (QSF): usr_refclk0

8.2.3 Network Clock
The three QSFP-DD modules are driven from dedicated FPGA transceivers. These transceivers require
a dedicated reference clock pin to use the cleanest clock source and hence support the highest of I/O
standards with tight jitter tolerances.
The Si5397 is I2C controllable from the BMC. The Card Support Package design demonstrates how to
program the Si5397A using a configuration file generated through the Skyworks ClockBuilder utility.
Instructions on how to generate new configuration files for the Skyworks parts can be found on the Bitt-
Ware Developer Site.
The Si5397 can be configured to generate its outputs (the transceiver reference clocks for the QSFP-
DDs) from a combination of its inputs (an on-board crystal in free running mode and three recovered
clocks from the FPGA).

Network Power-on Clock (From Si5397)
Each QSFP-DD bank is fed by one of the Si5397’s LVPECL coupled clock output signals. The Si5397
outputs 156.25 MHz by default at power-on. The Si5397 can be reprogrammed via I2C from the BMC;
refer to the Si5397 datasheet for details.
FPGA pin name (QSF): xcvr_refclk_0, xcvr_refclk_1, xcvr_refclk_2, xcvr_refclk_3

8.5 Startup Sequence
The IA-840f operates on the PCIe bus. TPVPERL is defined in PCIe CEM to be a minimum of 100ms
from 3.3V/12 volts being stable to when PERST# is de-asserted. Note this is a minimum time as defined
in the specification. The IA-840f configuration is based on the use of an Active Serial x4 QSPI flash inter-
face, which is a serial x4 interface.
The Agilex series FPGA configuration bitstreams that include PCIe default to activating the PCI HIP
Autonomous mode. This mode means that in the period between the initial FPGA section of the bit-
stream and the completion of the bitstream load when the device enters user mode, the PCIe HIP will
return retry requests for configuration TLPs. This extends the PCIe enumeration window timing.




© 2025 BittWare, a Molex company                                                                          54
The default factory clock file programmed into the IA-840f at cold boot from the BMC is set to enable test-
ing of the recovered clocks. With this programming file the initialization of the clocks at cold boot waits on
recovered clocks that are not present until the FPGA is configured fully. This results in an overall startup
time that is up to 5.5 seconds in total.
In the majority of desktop class systems, the IA-840f will miss the PCIe enumeration and will require a
warm restart to see the IA-840f enumerated on the PCIe bus. In server class systems the window for
enumeration is generally much longer. In server class system testing, the IA-840f has been shown to reli-
ably enumerate from cold boot. In some desktop class systems, the 5.5 second timing results in the host
motherboard disabling the PCIe clock to the physical slot because it does not detect the presence of a
PCIe device. To then detect the IA-840f on the PCIe bus, it can require two or three warm restarts.

9.2 Board Managment Controller (BMC)
The IA-840f features an advanced system monitoring subsystem, similar to those typically found on
today’s server platforms. At the heart of the board’s monitoring system lies a Board Management Con-
troller (BMC), which accepts PLDM commands. The BMC provides a wealth of features, including con-
trol of power and resets, monitoring of board sensors, FPGA boot loader, voltage overrides,
configuration of programmable clocks, access to I2C bus components, field upgrades, and PLDM mes-
saging. Access to the BMC is via PCIe or USB. The BittWare SDK also provides utilities and libraries for
communicating with the BMC components at a higher, more abstract level, allowing developers to
remotely monitor the health of the board. Refer to the BMC Reference Guide for more detail.

9.2.1 Features
The BMC subsystem is used to control:
   l   Power and reset sequencing
   l   Board support peripherals (such as programmable clock synthesizers)
   l   MCTP/PLDM support
From an environmental perspective, the BMC provides via PLDM:
   l   Power supply monitoring
   l   Current monitoring
   l   Power supply failure logging (volatile)
   l   Power consumption and temperature monitoring (FPGA, QSFP28 modules temperatures)
   l   Over temperature trip protection (FPGA blanks) and logging (volatile)
This environmental information is accessed via the software board monitor utility which runs over the
USB connection.
The BMC monitors the FPGA and the board temperature along with voltage, current, and power. The
BMC has access to several on-board sensors and implements a shutdown if levels are too high. For a
complete list of these sensors and their shutdown values, refer to the BMC Reference Guide for IA-840f.

9.4 I2C Devices
One of the BMC’s hardware I2C ports is directly connected to the PCIe bus for system management sup-
port and another is connected to a variety of components on board for status & control. All local devices,
DIMMs, and QSFP-DDs support 100 kHz operation.

9.4.1 PCIe I2C
An I2C port is routed to the PCIe fingers from the BMC. This interface is used for system level monitoring
and control through such protocol as PLDM and IPMI. It is an isolated interface since in some systems,
the signals may be active.

9.4.2 Shared I2C
The BMC and FPGA share an I2C bus that allows for the two devices to communicate with the QSFPs
and the on- board EEPROM. The BMC is the default master of the bus, and the FPGA is required to
request permission to gain control. On both I2C lines, SDA and SCL do not instantiate pull-ups in the
FPGA.

10.1 Overview
The IA-840f features multiple USB devices which are all accessible (through a USB hub) from either the
front panel or the rear panel Type-C connectors.
The USB connectors on the rear panel can be used to connect to a motherboard internal USB connector
or to daisy chain up to four boards together (for example to access multiple boards in a server with a
single motherboard internal USB connector).

   Note: For more information on deployment solutions in a BittWare TeraBox FPGA server, visit the
   TeraBox section on the BittWare website or contact your BittWare Sales representative for more
   information.

Both the front and rear USB connectors give access to the same USB devices:
  1. USB-Blaster II for JTAG access to the FPGA
  2. BMC for access to control and status port
  3. And a FPGA user-controller UART
The USB front panel header and the USB IN rear panel share the up-stream bus into the USB hub. The
front panel USB has priority over the rear panel USB. Plugging a cable into the front panel will dis-
connect USB traffic routed through the rear connector.

10.2 Board Features Accessible via USB
The USB port provides access to the BMC, USB UART, and USB Blaster. The IA-840f Max 10 FPGA
allows multiple entry points to access the configuration hardware (as well as monitoring and debug fea-
tures). Front and rear panel USB ports offer identical functionalities. Only one interface can be used at
any one time; the switchover is managed by an automatic circuitry. If both USB ports are connected, the
front panel USB takes precedence. In addition, it is possible to daisy chain up to four IA-840f boards
within the same system accessed by a single front or rear panel USB connector.

11.1 Power Specifications
The IA-840f board is designed to support a typical operating power consumption of 225W. The standard
Fan/Heatsink COTS solution supports 225 Watts cooling with an ambient inlet temperature up to 35C.
Under these conditions the FPGA die temperature will typically be kept below an operating junction tem-
perature of 85C.
You can read the FPGA fabric temperature via the BMC and estimate the power required by the FPGA
using Intel’s EPE tool available on the Intel website.

                             Table 24: Max Power Consumption Estimate

                             Device                        Max Power
                             Agilex                        177W
                             DDR4 (4 off)                  18W
                             QSFP-DD (3 off)               30W
                             Logic                         10W
                             PSU (85% efficiency)          41W
                             Total @85% PSU efficiency     225W



Important: The 177W max is an aggregate estimate for FPGA core power. Because the FPGA's core
supply is derived only from 12V EXT2, the EXT2 current limit then limits the max core current that can be
drawn before a BMC fatal threshold is detected and the board is shut down. For a more granular look at
thresholds, you can report the full list via the BMC PLDM accesses using the bw_card_monitor utility:

11.3 Power Requirements
Power requirements for the IA-840f are application-specific. The card power draw might go from low, if
the FPGA is unconfigured, to medium when the FPGA is programmed with an FPGA design. FPGA
designs with high resource utilization, high toggle rate, and high clock frequency will increase the card
power draw, which might approach the card’s max power.


   Warning! Be sure the IA-840f does not go from high power to no power all at once as it may cause
   a voltage spike on the FPGA core supply that could damage the FPGA.


If you are doing high power designs, you should not turn your designs on or off all at once; instead, ramp
up and ramp down. If you have a runaway FPGA you need to shut off, you can help prevent damage by
lowering the core voltage via the BMC before shutting down the FPGA.

11.4 Power Monitoring
As noted in Card Management, the BMC monitors the power supplies in real time. You can use the
SDK’s BMC utility to read the values, or you can use MCTP/PLDM, as described in the BMC Reference
Guide for IA-840f. The BMC Reference Guide also lists the sensors that the BMC is monitoring.

Appendix A: PROM Format

This section details the format of the VPD EPROM. The EPROM is reserved for VPD (Vital Product Data)
information and BittWare board information. The format is a fixed offset format fit in a 256 byte range. The
first 4 bytes are a signature (“BWPF”) that lets software know the format; this along with the format version
will allow for compatible future changes.

                                      Table 27: VPD EPROM Format
     Address    Length    Value                                Type
     0          4         Signature “BWPF”                     String fixed value
     4          1         Format version                       Int
     5          15        Serial Number                        String
     20         48        Product Code                         String
     68         10        Revision                             String in the format of 0.1.2.3.4
     78         8         Manufacture Date                     64-bit Unix time format
     86         6         Base MAC                             MAC format: MAC address stored at 6 bytes
     92         1         Number of sequential MAC addresses   Integer
     93         16        UUID                                 UUID format stored as array of 16 bytes
     109        19        Reserved                             Reserved
     128        128       Customer Data                        Customer defined



* String format: NULL (0) terminated ASCII encoded string
